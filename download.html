read this before you download

Cloud iNIT ships one build per platform. Check your machine against the rules below first — an unsupported system fails at install, not at first boot.

Windows

  • Windows 10 or Windows 11 only, 64-bit. These are the only versions the installer supports.
  • Windows 8.1, 8, 7 and anything older will not install, and will not be patched to.
  • Some older machines are fine. Age of the laptop or desktop does not matter — if it runs Windows 10 or 11 with 4 GB of RAM, it is supported.
  • Keep Windows updated, and allow the installer through SmartScreen and any admin prompt.

macOS

  • MacBook with Apple silicon only — M1, M2, M3, M4 and later chips.
  • Intel-based Macs are not supported. There is no Intel build.
  • macOS must be up to date. Install every pending system update before you run the installer.
  • On first launch use right-click → Open, then allow it under Privacy & Security if Gatekeeper holds it.

Check yours — Windows: Settings → System → About. Mac: Apple menu → About This Mac; the Chip line must read Apple M-something.

Online sandbox or offline build

Both builds run the identical nine-stage boot sequence. The difference is whose cloud accounts they run against and how much you can push through them.

Online sandbox · free

Runs against shared accounts we manage across AWS, Azure, and GCP. Rate-limited, and it goes through a short automated review before it activates, because capacity is shared with everyone else on the same release window.

  • Best for coursework, demos, and trying a stage you have not used before
  • No cloud credentials of your own required
  • Auto-expires at the end of the release window

Offline build · your accounts

Installs locally and runs the same sequence against your own cloud credentials. No shared capacity, so no queue and no rate limit — the boot log reflects your actual account limits, not ours.

  • Best for work you intend to keep iterating on
  • Credentials stay local, in an OS-native secret store
  • Tears down on command, rotating anything the identity stage issued

before you install

Install questions

My Mac is Intel-based. Is there anything I can run?
Not locally — the macOS build is Apple silicon only and there is no Intel build planned. Use the online sandbox from a browser on that machine, or install the Windows build on a Windows 10/11 machine instead.
Will it run on an older Windows laptop?
Yes, provided that laptop is on Windows 10 or 11 with 4 GB of RAM and 1.2 GB free. Hardware age is not the constraint — the Windows version is. Windows 8.1 and older cannot install it at all.
Do I need admin rights to install the offline build?
On Windows, yes — the installer registers a local service that runs the boot engine. On macOS a standard user account is enough; no root privileges are required.
Can I switch from the sandbox to an offline build later without starting over?
Yes. Boot logs and stage configuration export from a sandbox session and import into an offline build, so you do not have to re-walk the sequence from stage 1 — only the credentials at the identity stage need to be re-issued against your own accounts.
What if the installer fails partway through?
Re-running the installer resumes from the last completed step rather than starting over. If a step keeps failing, the installer log (written next to the installer) shows which prerequisite — usually free disk space or a blocked network port — is missing.
How do I uninstall cleanly?
Uninstalling tears down any active sandboxes first, rotates or revokes credentials the identity stage issued, then removes the local install. Running the uninstaller — rather than deleting the app folder by hand — is what triggers that teardown.

Not sure which build?

Online sandboxes are free and reviewed inside your release window. Offline builds skip the queue entirely and run on your own accounts.

cloudinit/why
01 — PRINCIPLES

Built for the next boot, not the last one

Most platforms bolt automation on top of infrastructure that was never designed for it. Cloud iNIT starts from the boot sequence itself — every service, every region, every credential comes online in a predictable, auditable order.

No steep learning curve, no vendor lock waiting at step nine. If a stage can't be explained in one sentence, it doesn't ship — that's the only feature-review process this platform has ever needed.

predictable

Order over improvisation

Every boot follows the same nine stages, in the same order, whether it's a solo student sandbox or a production rollout. Nothing races, nothing guesses.

auditable

Nothing starts silently

Every service that comes online writes a line to the boot log — timestamped, tagged, and visible. If you can't see it start, it isn't running.

reversible

Undo is a first-class stage

Credentials rotate, sandboxes reset, deployments roll back — through the same init path they came up through, not a separate emergency script.
